قم بتحديث كود الواجهة الأمامية (Frontend) ليدعم التسجيل المتزامن عالي الكثافة (50+ شخص في نفس الثانية) بدون أي تهنيج أو ضياع أو خلط بيانات، مع إضافة أداة اختبار ضغط وتنظيف داخل لوحة المنظمين المخفية (?admin=true)، وفق المتطلبات التالية بدقة:

1. آلية الإرسال المقاومة للضغط (Smart Retry + Idempotency):
- عند الضغط على زر "تأكيد التسجيل":
  * عطّل زر الإرسال فوراً (disabled) لمنع الضغط المزدوج.
  * أنشئ معرّفاً فريداً ثابتاً للطلب: `const requestId = crypto.randomUUID ? crypto.randomUUID() : ('req_' + Date.now() + '_' + Math.random().toString(36).slice(2, 10));`
  * أرسل `requestId` داخل جسم طلب الـ POST (`action: "register"`).
- أنشئ دالة `postWithRetry(payload, onRetryStatus, maxRetries = 8)`:
  * ترسل POST إلى `API_URL` باستخدام `headers: { "Content-Type": "text/plain;charset=utf-8" }`.
  * إذا فشل الاتصال (Network Error / HTTP 429 / HTTP 5xx) أو رجع الرد `{ success: false, retryable: true }`:
    - لا تُظهر خطأ للمستخدم!
    - احسب تأخيراً عشوائياً متصاعداً (Exponential Backoff + Jitter): مثلاً `Math.min(5000, 400 * Math.pow(1.4, attempt)) + Math.random() * 600`.
    - أظهر رسالة مطمئنة على الزر: `"جاري تثبيت حجزك في الطابور... يرجى عدم إغلاق الصفحة (محاولة X)"`.
    - أعد الإرسال بنفس الـ `requestId` تماماً (حتى يمنع السيرفر أي تكرار).
  * إذا رجع خطأ منطقي غير قابل للإعادة (`retryable` غير موجودة مثل: "البص اتملا" أو "القروب اكتمل" أو "الرقم ناقص"): توقف فوراً واعرض رسالة الخطأ للمستخدم وأعد تفعيل الزر.
  * عند النجاح (`success: true`): أظهر رقم الطابور (`data.seqNo`) ووقت التثبيت (`data.timestamp`) ثم حوّل للواتساب.

2. عرض الترتيب الدقيق في لوحة المنظمين (?admin=true):
- أضف عموداً في جدول المنظمين يعرض **رقم الطابور (`#seqNo`)** و**وقت التثبيت بأجزاء الثانية (`timestamp`)**، وميّز أي صف يحمل `isTest: true` بشارة صفراء مكتوب عليها "اختبار ضغط".

3. قسم "اختبار الضغط والتزامن (Stress Test)" داخل لوحة المنظمين فقط (?admin=true):
أضف قسماً مخصصاً في أعلى لوحة المنظمين يحتوي على:
- خانة لتحديد عدد التسجيلات المتزامنة (القيمة الافتراضية: `50`).
- زر: **"تشغيل اختبار ضغط (50 تسجيل في نفس اللحظة)"**:
  * يولّد 50 طلباً فريداً تماماً، كل طلب له:
    - `requestId`: `'test_' + batchId + '_' + i`
    - اسم ثلاثي مميز: `اختبار ضغط رقم${i}` (مثال: `اختبار ضغط رقم1` إلى `اختبار ضغط رقم50`)
    - رقم مصري صحيح ومميز: `+20` متبوعاً بـ `10000000` + رقمين (مثال: `1000000001` إلى `1000000050`)
    - توزيع متوازن على `bus1`/`bus2` والألوان الأربعة والمستلمين (`mekhail`/`fayez`) وطرق الدفع
    - `isTest: true` و `secret: ADMIN_SECRET`
  * يطلق الطلبات الـ 50 **معاً في نفس اللحظة** عبر `Promise.all` باستخدام نفس دالة `postWithRetry` (مع عداد مباشر يظهر على الشاشة: تم الإرسال / نجح / أُعيدت محاولته تلقائياً / فشل).
  * بمجرد انتهاء الطلبات كلها، يجلب تلقائياً `adminData` من Google Sheet ويقوم بـ **فحص سلامة البيانات آلياً (Integrity Verification)**:
    1. يتأكد أن عدد الطلبات الواصلة في الشيت يطابق 50 من 50 بالضبط.
    2. يتأكد أنه لا يوجد أي `requestId` مكرر (صفر تكرار).
    3. يتأكد أن كل اسم يطابق رقمه وباصه ولونه بالضبط (صفر خلط بيانات).
    4. يتأكد أن أرقام الطابور (`seqNo`) متسلسلة ومنظمة بدون أي تداخل.
  * يعرض تقريراً تفصيلياً أخضر بالنتائج ووقت الاختبار الإجمالي، ويحدّث جدول المنظمين لتشاهد الـ 50 تسجيلاً بنفسك داخل اللوحة.
- زر أحمر: **"مسح بيانات الاختبار وتنظيف الشيت بالكامل"**:
  * يرسل `{ action: "clearTestData", secret: ADMIN_SECRET }` عبر POST.
  * يمسح كل السجلات الموسومة بـ `TEST` فقط من Google Sheet (بدون لمس أي تسجيل حقيقي)، ويعيد تصفير العداد إذا كان الشيت فارغاً، ثم يحدّث لوحة المنظمين لتصبح نظيفة 100% وجاهزة لإطلاق الرحلة.
